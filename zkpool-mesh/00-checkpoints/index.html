Checkpoint Methodology

In multi-language, multi-runtime projects (Noir, Sunspot, Rust, Anchor, TypeScript, browser WASM), most bugs appear not inside a single component, but at the boundaries between them:

  • compiler version mismatches,
  • reversed byte order (endianness),
  • discrepancies in public input serialization,
  • outdated ACIR files in the frontend.

The checkpoint methodology solves this problem: after each stage, key artifacts are saved into a local .checkpoints/NN-name/ directory, and sha256sum checksums are recorded alongside the commit hash.

Recording Rule

Section titled “Recording Rule”

After each stage or significant code change:

  • Compute artifact checksums via sha256sum and write them to .checkpoints/NN-name/manifest.txt.
  • Save the current commit hash to .checkpoints/NN-name/commit.txt.

At the next stage where another service or container consumes these artifacts, checksums are verified.
If hashes do not match, work stops until the root cause is found.
An artifact can be restored from GitHub using the commit hash.
