Stage 1: Baseline

The baseline establishes a reproducible build, deployment, and end-to-end verification environment for the entire zkpool-mesh stack.
It separates network-bound tool and dependency fetching (warming cache/ via scripts/boot.sh and scripts/boot/ modules) from offline container builds orchestrated by a modular Makefile (infra/mk/{infra.mk, chain.mk, stack.mk, test.mk, diag.mk}).

Network Access Boundary: Pre-Cached vs Online Steps

Section titled “Network Access Boundary: Pre-Cached vs Online Steps”
  • Tools and project dependencies (scripts/boot.sh):
    base Docker image tarballs, Go, Rust, Solana CLI / Agave, Anchor, Node.js, pnpm, Nargo, Sunspot, platform-tools, all Cargo crates for the project and sunspot/gnark-solana (cache/cargo-registry/ and cache/cargo-git/), and npm/pnpm package archives (cache/pnpm-store/) are downloaded upfront into cache/.
  • Contract build and deployment (make chain):
    with platform-tools, cargo-registry, and cargo-git cached, building the verifier (sunspot deploy), building zk_pool (anchor build –no-idl), and compiling scripts/pool-init run from the local cache;
    on the first run of anchor idl build in a fresh container, Cargo may only fetch auxiliary IDL generator crates if not warmed beforehand.
  • System packages during image builds (make infra):
    when building Dockerfile.base, Dockerfile.node-base, and Dockerfile.test, apt-get fetches core system utilities and development headers from Debian 13 repositories (libssl3, libssl-dev, libudev1, libclang-dev, protobuf-compiler, build-essential, pkg-config, git, curl, libatomic1).
  • Supply-chain metadata during Node installs (make infra / make stack):
    running pnpm install –frozen-lockfile reads package archives from the cached store at /home/i/.local/share/pnpm/store while querying registry.npmjs.org only for JSON metadata required by pnpm v12 supply-chain checks.
  • Runtime isolation across four containers:
    Rust/Solana/Noir/Sunspot build toolchains are kept separate from Node.js and the static nginx frontend.
  • Independent Makefile zones:
    infrastructure, on-chain contracts, application services, tests, and diagnostics are split into dedicated infra/mk/ modules that can be executed independently.

1. Modular Cache Warming Flow (scripts/boot.sh and scripts/boot/)

Section titled “1. Modular Cache Warming Flow (scripts/boot.sh and scripts/boot/)”

The entrypoint scripts/boot.sh runs on the host (make boot), reads target versions from .env:

  • ANCHOR_VERSION,
  • NODE_VERSION,
  • PNPM_VERSION,
  • GO_VERSION,
  • CARGO_DENY_VERSION,
  • SOLANA_PLATFORM_TOOLS_VERSION

defaulting to the latest release when empty, and sources four modules under scripts/boot/:

  • scripts/boot/common.sh — logging helpers, .env loading, and building the temporary zkpool-boot-builder:latest image on debian:13 (user i, UID 1000).
  • scripts/boot/toolchain.sh — downloading and compiling core toolchains:
    • boot_go — downloads and unpacks Go into cache/go/.
    • boot_solana_dev — installs rustup (stable), Solana CLI / Agave (release.anza.xyz), anchor-cli (without avm), Node.js via nvm, cargo-deny, cargo-audit, and standalone cargo-build-sbf, then runs a dummy build to populate cache/solana-dev/platform-tools/.
    • boot_sunspot — clones reilabs/sunspot and compiles the binary into cache/sunspot/go/sunspot.
    • boot_nargo — installs the latest nargo binary into cache/nargo/nargo.
    • boot_pnpm — installs the package manager into cache/pnpm/.
  • scripts/boot/deps.sh — pre-fetching project dependencies:
    • boot_cargo_cache — runs cargo fetch –locked across every Cargo.toml in the repository (sunspot/gnark-solana, onchain, scripts/, services/, tests) and warms anchor idl build dependencies into cache/cargo-registry/ and cache/cargo-git/.
    • boot_pnpm_store — runs pnpm fetch –frozen-lockfile for services/merkle and web, saving package tarballs into cache/pnpm-store/.
  • scripts/boot/env.sh — preparing base Docker images and the deployment wallet:
    • boot_images — pulls and saves six base images into cache/images/*.tar (debian:13, postgres:16-alpine, redis:7-alpine, prom/prometheus:v2.55.0, grafana/grafana:11.3.0, nginx:alpine), then loads them into local Docker.
    • boot_wallet — generates the local deployment wallet solana/id.json and logs output to .secrets/keygen.log (without leaking secrets to stdout or triggering automatic airdrops).

Once scripts/boot.sh finishes, the temporary zkpool-boot-builder:latest image is removed.

2. Four Custom Images and Containers

Section titled “2. Four Custom Images and Containers”

infra/compose.yml and infra/docker/ divide the stack into four custom container images:

  • zkpool-base: Builds Anchor programs, Noir circuits, Sunspot artifacts, and Rust services (with pre-warmed cache/cargo-registry/ and cache/cargo-git/); runs zkpool-backend (:4001) and zkpool-prover (:4002)
    • Dockerfile: infra/docker/Dockerfile.base
    • Container: zkpool-mesh
  • zkpool-node-base: Node.js 26 + pnpm 12 runtime (with pre-warmed cache/pnpm-store/) for the Merkle tree service (:4003)
    • Dockerfile: infra/docker/Dockerfile.node-base
    • Container: zkpool-merkle
  • zkpool-frontend: Builds the Vue 3 + Vite frontend on top of zkpool-node-base and serves static assets via nginx:alpine (:8080)
    • Dockerfile: infra/docker/Dockerfile.frontend
    • Container: zkpool-web
  • zkpool-test: Local solana-test-validator running as UID 1000 (RPC :8899, faucet :9900) backed by the zkpool-validator-ledger volume
    • Dockerfile: infra/docker/Dockerfile.test
    • Container: zkpool-validator`

In addition, infra/compose.yml starts supporting infrastructure services with health checks:

  • zkpool-postgres (postgres:16-alpine, :5432, zkpool-postgres-data volume) — stores indexed commitments and Merkle root history.
  • zkpool-redis (redis:7-alpine, :6379, zkpool-redis-data volume) — caches Merkle tree size and current root.
  • zkpool-prometheus (prom/prometheus:v2.55.0, :9090) - metrics scraping.
  • zkpool-grafana (grafana/grafana:11.3.0, :3000, admin/admin) — dashboards.

3. Version Pinning and Network Switching

Section titled “3. Version Pinning and Network Switching”
  • Version pinning (scripts/pin-versions.sh):
    immediately after building images in build-images, scripts/pin-versions.sh runs automatically.
    It inspects ephemeral zkpool-base and zkpool-node-base containers, reads the installed versions of anchor, solana, nargo, rustc, go, cargo-deny, solana-platform-tools (from /home/i/.cache/solana), node, and pnpm, and writes the exact *_VERSION= values back into .env.
  • Switching between localnet and devnet (scripts/switch-network.sh):
    updates SOLANA_NETWORK, SOLANA_RPC_URL, DEFAULT_RPC, and RPC_URL in .env and .env.example, cluster in onchain/Anchor.toml, and VITE_SOLANA_RPC_URL in web/.env.
    By default, the project targets the local validator (localnet, http://solana-test-validator:8899).

4. Modular Makefile and Functional Zones

Section titled “4. Modular Makefile and Functional Zones”

The root Makefile defines shared variables, make help, make boot, and make redeploy, while functional zones live in infra/mk/:

Zone 1 — boot (Host and cache/)

Section titled “Zone 1 — boot (Host and cache/)”

Warms cache/ and creates solana/id.json.

Zone 2 — infra (infra/mk/infra.mk)

Section titled “Zone 2 — infra (infra/mk/infra.mk)”

Executes three steps:

  • build-images — ensures .env exists (copying .env.example if missing), loads tarballs from cache/images/, builds the four custom images, and invokes make pin-versions.
  • up — starts all containers with docker compose -f infra/compose.yml up -d.
  • migrations — applies services/backend/migrations/001_init.sql to zkpool-postgres.

Zone 3 — chain (infra/mk/chain.mk)

Section titled “Zone 3 — chain (infra/mk/chain.mk)”

Runs five deployment steps inside ephemeral zkpool-base containers attached to infra_default:

  • airdrop — verifies infra_default exists, checks wallet balance, and requests solana airdrop 100 if balance is below 2 SOL.
  • Compiles withdrawal with nargo compile, generates proving and verifying keys via sunspot compile and sunspot setup, builds the Groth16 verifier (sunspot deploy), and deploys it to the local validator over HTTP RPC (–use-rpc).
  • Injects the new VERIFIER_PROGRAM_ID into onchain/programs/zk_pool/src/constants.rs and .env.
  • Rebuilds zk_pool (anchor build –no-idl –tools-version $$PT_VER, reading platform-tools version from .env or /home/i/.cache/solana), builds the IDL (anchor idl build), deploys the program with –use-rpc, and syncs PROGRAM_ID across lib.rs, Anchor.toml, and .env.
  • Initializes the pool PDA via scripts/pool-init (using preflightCommitment: “confirmed”), writes POOL_ADDRESS to .env, and runs make sync-ids.

To close stale program buffers and reclaim SOL, run make chain-close using addresses listed in cache/old-programs.txt.

Zone 4 — stack (infra/mk/stack.mk)

Section titled “Zone 4 — stack (infra/mk/stack.mk)”

Executes sequentially:

  • validate-spec — validates circuits/withdrawal/spec.json.
  • sync — copies ACIR artifacts to services/merkle/ and web/public/circuits/ (make sync-check provides a read-only CI check).
  • check — verifies withdrawal.ccs and withdrawal.pk from Zone 3 exist.
  • deps and mesh — runs pnpm install –frozen-lockfile inside zkpool-merkle, builds release binaries for zkpool-backend and zkpool-prover inside zkpool-mesh, and rebuilds the static frontend via docker compose build frontend.
  • e2e-build — compiles e2e-deposit, e2e-deposit-split, and e2e-withdraw.
  • services — cleanly restarts zkpool-merkle and zkpool-mesh, loads .env, and starts node src/server.js (MERKLE_PORT=4003), zkpool-prover (:4002, SUNSPOT_BIN=/home/i/sunspot/go/sunspot), and zkpool-backend (:4001) with HTTP health checks.

Zone 5 — Unit and Integration Tests (infra/mk/test.mk)

Section titled “Zone 5 — Unit and Integration Tests (infra/mk/test.mk)”

Runs test suites inside ephemeral containers:

  • make test-circuits — runs nargo test across all Noir packages (poseidon, hash2, hashes, withdrawal — 49 tests).
  • make test-rust — runs cargo test for validate-spec, sync-circuits, backend, and prover.
  • make test-onchain — runs cargo test in the onchain workspace.
  • make test-merkle — runs pnpm test for the Merkle tree service.

6. End-to-End Verification and Diagnostics (infra/mk/diag.mk)

Section titled “6. End-to-End Verification and Diagnostics (infra/mk/diag.mk)”

Run the single-note end-to-end flow:

This runs e2e-deposit inside zkpool-mesh (with preflightCommitment: “confirmed”), extracts the secret note to /tmp/note.json, polls GET http://localhost:4001/api/commitments until indexed, and runs e2e-withdraw to send funds to E2E_RECIPIENT (logs saved to /tmp/e2e-deposit.log and /tmp/e2e-withdraw.log).
To test a 3-note split deposit and three independent withdrawals, run make e2e-split.

Rebuild from scratch

Section titled “Rebuild from scratch”

To wipe containers, volumes, and images while preserving cache/ and :

Diagnostic targets in infra/mk/diag.mk:

  • make status — container states, HTTP status codes for health endpoints (4001, 4002, 4003), and Postgres/Redis entry counts.
  • make verify — checks PROGRAM_ID / VERIFIER_PROGRAM_ID consistency, inspects the on-chain pool account, recent Postgres roots, Redis tree state, and API responses (/api/commitments, /api/root, /api/proof).
  • make logs — tails recent logs from merkle, backend, and prover.
